# 电梯公寓大逃杀 · 设计与规则说明

> 版本 v7 · 2D 网页模拟游戏 · 单机对 AI
> 本文档是需求和规则的唯一来源，代码中的数值以 `src/config.js` 为准，两者冲突时以文档意图为准再同步代码。
> 版本号写在 `src/config.js` 的 `EK.VERSION`，界面标题和教程里会显示。

## 1. 一句话

20 层公寓里，3 个小孩靠躲、跑、坐电梯拖时间换分数，2 个杀人犯靠共享频道围猎；玩家既可以当小孩逃生，也可以当杀人犯抓人，观看方式分上帝视角和有限视角。

## 2. 核心循环

- 一局固定时长（默认 180 秒），**没有出口、没有救援**，小孩唯一的得分方式就是活着。
- 小孩分数 = 存活时长累计（每秒 1 分）；杀人犯分数 = 抓到的人数 × 100。
- 计时结束结算；中途被抓的小孩退出本局（不再得分），其余小孩继续。
- 所有小孩全部被抓 → 本局提前结束，按已过时间结算。

## 3. 角色

| 角色 | 数量（默认，可调） | 移速 | 信息 |
| --- | --- | --- | --- |
| 小孩 | 3 | 2.2 m/s | 互相孤立，只能看见自己视野内的东西 |
| 杀人犯 | 2 | 2.75 m/s（1.25 倍） | **共享通讯频道**，但只共享各自亲眼所见 |

### 3.1 共享频道

- 杀人犯看到小孩的一瞬间，把「小孩编号 / 所在楼层 / 所在区域 / 时间」写进频道。
- 其他杀人犯立刻知道这条情报；情报 **6 秒** 后过期（视为追丢）。
- 频道里没有的东西 AI 不知道：不知道没被看见的小孩在哪，不知道关门后的轿厢里有谁。
- 玩家当杀人犯时同样受限（有限视角下），开上帝视角属于「观战作弊」，胜负不计入AI评估。

## 4. 建筑

- **20 层**，每层从左到右固定为：`楼梯口 A — 左楼道 — 电梯厅（电梯 C、电梯 D）— 右楼道 — 楼梯口 B`。
- **2 部楼梯**（楼梯 0、楼梯 1），**2 部电梯**（轿厢 C、轿厢 D）。
- 左楼道与右楼道**等长**（`corridorSideM`，默认 9.5 m，界面可调 4–16 m）；电梯厅宽 3.6 m，位于两种楼道之间。
  总长度 `L = 2 × 楼道长 + 电梯厅宽`（默认 22.6 m）；楼梯口距楼层两端各 0.7 m。
- 两部电梯门挨得很近（相距 1.8 m），视为同一个地点「电梯厅」。

### 4.1 楼梯连接（关键规则）

每个楼梯口通过楼梯连接上一层的**另一个**楼梯口：

- `A(n) ↔ B(n+1)`（楼梯 0），`A(n) ↔ B(n-1)`（楼梯 0）
- `B(n) ↔ A(n+1)`（楼梯 1），`B(n) ↔ A(n-1)`（楼梯 1）

即从 8 层 A 往上走，落在 9 层 B；从 8 层 A 往下走，落在 7 层 B。端点层（1 层、20 层）只能单向。

### 4.2 可见性规则表

| 观察者位置 | 目标位置 | 是否可见 |
| --- | --- | --- |
| 楼梯口 A | 同层电梯厅 | ✅ 可见（视距内） |
| 楼梯口 B | 同层电梯厅 | ✅ 可见（视距内） |
| 楼梯口 A | 同层楼梯口 B | ❌ 永远不可见 |
| 楼梯口 A | 另一层任何位置 | ❌ |
| 电梯厅 | 电梯厅（同层） | ✅ 视距内可见 |
| 电梯厅 | 另有开门轿厢内的人 | ✅ 门开着才看得见 |
| 轿厢内 | 同轿厢的人 | ✅ |
| 轿厢内 | 轿厢外 | ❌（关门后一无所知） |
| 轿厢内 | 其他轿厢 / 楼层 | ❌ |
| 楼梯段内 | 同一段楼梯上的人（含迎面方向） | ✅（可相遇、可被抓） |
| 楼梯段内 | 楼层 / 另一部楼梯 | ❌ |

补充：

- 站在电梯厅（或走廊端点）可以**瞬间读取两部电梯的当前楼层与运行方向**（楼层显示屏）。其他位置读不到。
- 轿厢里的人只看得到**本轿厢的楼层和运行方向**，看不到各楼层有哪些呼梯请求，也读不到另一部梯。
- 同一层走廊内，视距为 14 m（小孩）/ 16 m（杀人犯），减去「A↔B 互不可见」的硬规则。

### 4.3 看不到时的电梯读数（记忆与估算）

- 只有「站在电梯厅」或「在该轿厢里」时才拿得到真实状态；离开后界面不再实时更新。
- 界面显示的是**最后一次看到的位置，按当时方向以恒定速度外推**得到的估计值，楼层后面加 `?`（`Perception.carDisplay`）。
- 从未看到过 → 显示 `??`。
- 重新回到电梯厅 / 进入轿厢 → 立刻刷新为真实值（`Perception.rememberCars` 每次观察到就覆盖记忆）。
- 这条规则对玩家和 AI 一样生效，也是 AI 拿电梯线索做推理的基础。

## 5. 电梯

### 5.1 物理参数（默认值，界面可调）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 层间运行时间 | 2.0 s/层 | 恒定速度，匀速 |
| 开门时间 | 1.5 s | |
| 开门保持 | 1.5 s | 无人进出时 |
| 关门时间 | 1.5 s | |
| 关门被打断 | 重新开门 | 关门途中有人进入门区，或该层呼梯键被按 |
| 载重 / 容量 | 不限 | 默认不设容量上限 |
| 待机 | 原地 | **没有**「空闲一段时间回 1 楼」的设定 |
| 上下客 | 整厅可达 | 两部梯门相距 1.8 m，站在电梯厅里 2 m 内都能上任何一部开门的梯 |

### 5.2 运行逻辑（SCAN / 方向事件队列）

实现：`src/model/elevator.js` 的 `wantsStopAt()` / `queueFor()` / `aheadStops()` / `plan()` / `move()`。

**核心：每个方向有自己的「事件队列」，每帧重算；当前方向跑完再考虑换向。**

1. **两个方向的队列**
   - 本层事件：轿厢里按的楼层，**以及**门外同方向的呼梯 → 算**当前方向**的队列；
   - 门外**反方向**的呼梯 → 算**反方向**的队列。
   - 任一时刻有人按按钮、或电梯到任何一层，队列都重算一遍（`queueFor(dir)` 都是现算的，没有缓存）。
2. **逐层确认**：`move()` 每走到一个整层就问 `wantsStopAt(楼层, dir)`：
   - 上行途中经过的楼层，只要有人按了 **▲**，就停；下行同理停 **▼**。
   - **不管这个呼梯派给了谁**——只要灯还亮着、方向一致就停。
   - 反方向呼梯不停（上去时经过有人按 ▼ 的楼不停）。
3. **队列跑完才换向**（`plan()`，每次停靠关门后、每次到层都走一遍）：
   1. 就在本层且该停（轿厢指令 / 同方向呼梯 / 待机时任何呼梯）→ 开门；
   2. 本层只剩反方向呼梯 → **原地补开一次门**把两个方向一起清掉（每次停靠只补一次，`reopenedForOpposite`，防止反复开门）；
   3. 正方向队列还有前方任务 → 继续走（**方向不变**；延长线上出现新任务会自动续上）；
   4. 正方向空了、反方向有任务 → **立即掉头**（只在整层做，避免在两层层之间来回摆）；
   5. 两个方向都空、但还有没处理的呼梯 → **立刻朝最近的那层出发**，不许待机摸鱼；两部梯可以同时奔同一个呼梯，谁先到谁服务，另一部到了发现请求已清就继续找下一个；
   6. 真的一条请求都没有 → **原地待机，不再移动**；如果正好停在非整数楼层（3.5 这种），就沿当前方向挪到最近的整层再停（向上 → 4，向下 → 3）。
4. 端点（1F / 20F）不需要特殊处理：到端点后前方队列必然为空，走第 4/5 步。
5. 呼梯按钮两种模式（`elevator.hallButtons`）：`shared` 公用一套（群控），`split` 每部梯一套。停靠只解除**与本方向一致**的呼梯（`world.onCarOpening`），反方向的按钮继续亮着。
6. 电梯内**任何人都能按轿厢按键**（小孩、杀人犯都会按，也会按反方向制造麻烦）。
7. 同一次停靠最多被挡 3 次，超过后强行关门，避免被卡死在某一层。
8. 等电梯超过 10 秒（`aiWaitTimeout`）的人会放弃等待、改走楼梯。

### 5.2.1 呼梯按钮与轿厢按键的界面

- **呼梯按钮**回到 v4 的位置：每层电梯厅左边是 C 的 ▼▲、右边是 D 的 ▼▲（公用模式：左 ▼ / 右 ▲），和楼层横条对齐。
- **楼层标识就是轿厢按键**：每层左右两端各有一个带框的 `NN F`，左边是 C 梯的、右边是 D 梯的。
  - 按下 → 框变高亮；到层或取消 → 弹起、恢复背景色。
  - 只有「看得到电梯状态」时才会出现框：上帝视角、身处轿厢、或杀人犯共享电梯视野。
  - **在轿厢里只能按自己这一部的框**；按另一部会提示「只有身处 D 梯里才能按它的轿厢按键」。
- **旁观 + 上帝视角（局外人）可以按任何按钮**：任意楼层的呼梯、任意一部梯的轿厢按键（`world.freePlay()`）。
- **开关门键分两组**：左边一组只属于 C 梯，右边一组只属于 D 梯，都在 9F–10F 的高度（开门键对齐 10F、关门键对齐 9F）。符号是现代电梯样式：两个正三角形，**尖角朝内相对 = 关门**、**尖角朝外 = 开门**，中间一条细竖线（`renderer.drawDoorIcon`）。桌面在画布两侧，触屏在底部触控栏，也可以用 `Q` / `E`。
  - 只有「身处的电梯」那一组可以按；旁观 + 上帝视角两组都能按。
  - **开门键**：门开着 → 刷新关门倒计时；正在关门 → 立刻变回开门并刷新倒计时；闲置停在整层 → 直接把门打开；运行中无效。
  - **关门键**：门开着 → 立即进入关门过程；其他状态无效。
- **两边面板独立判断可见性**（`sideVisible(side)`），三种状态：**没有框**（看不到这部梯的面板，只剩楼层号）/ **暗框**（看得到、没按）/ **高亮框**（按下了）。
  - 上帝视角 / 旁观者：两边都看得到。
  - 小孩在 C 梯里：只看得到 C 的面板，D 那边没有框（看不到 D 按了哪些层）。
  - 玩家是杀人犯（有限视角）：**只要有一名杀人犯在 C 梯里，就能看到 C 的面板**；D 同理（`world.killersAlive()` 里有人在那部梯里）。
  - 其他情况（小孩在楼层上）：两边都没有框。
### 5.3 电梯博弈

- 轿厢内可以抓人：杀人犯跟进轿厢，门一关就是瓮中捉鳖。
- 堵门：杀人犯站在门区里，门关一半被挡会重新开门，形成「卡门」。
- 抢门：小孩可以在门快关时冲进轿厢，也可以按开门键救自己。

### 5.4 轿厢内的操作

- 楼层键就是每层两端的**楼层标识框**（左 C、右 D）：点一下登记（框变高亮），再点一下取消；可以同时按好几层。
- 按过的框对「看得到电梯状态的人」都可见：进一部空梯，也能看到之前有人按过、还没被服务的楼层。
- **在轿厢里只能按自己这一部的框**；另一部的框能看到（信息），按了会提示。
- 轿厢里没有 Open/Close 之外的面板：`开门 / 关门` 在画布左上角（窄屏在底部触控栏），也可以用 `Q` / `E`。
- 出梯用 `空格`（只在门开着时有效），不会自动在某一层替你下梯。
- 轿厢里看不到各层的呼梯请求，只能看到本梯的楼层和运行方向。
## 6. 抓捕

- 同一空间内（同一层走廊 / 同一轿厢 / 同一楼梯段）距离小于判定范围开始抓捕：走廊与轿厢 0.8 m，楼梯段 1.2 m。
- 抓捕需要持续接触 **0.4 s**（可调，设为 0 即瞬间抓）；拉开距离则中断。
- 被抓小孩立即从场上移除，计分停止。

## 7. AI

### 7.1 小孩（v6：只凭记忆，不全知）

状态机：`游走 → 察觉威胁 → 逃离 → 选路线（楼梯 / 电梯）→ 认准目标换层 → 到站歇一会儿 → 再游走`。

- 看见杀人犯且距离小于危险阈值（默认 9 m）→ 沿走廊反向逃离，优先逃向**离杀人犯更远的楼梯口**；反应时间 `kid.reactionSec`（0.2 s）后才开跑。
- **威胁记忆（v6）**：看见杀人犯时记下「哪一层、哪个位置、什么时候」（`threatMem`），`ai.kidMemorySec`（8 s）内有效，形成以该层为圆心、`ai.kidDangerRadius`（±1 层）的危险区：
  - 选目标层时危险区会被强烈扣分（实测危险区被选中的概率 0%）；
  - 如果自己正站在危险区里 → 立刻想换层；
  - 在本层走动时也尽量往远离记忆点的方向走。
  - 小孩**不再读取杀人犯的真实位置和频道**（v5 之前是"全知"，属于作弊）。
- **认准目标（v6）**：决定去 X 层后锁定 `ai.kidCommitSec`（4 s），中途不改主意；到站后先歇 `ai.kidRestSec`（2 s）再重新决定，避免在两层之间抖。
- 换层选择：比较「到楼梯口的时间 + 爬楼时间」与「电梯预计到达时间 + 运行时间」；电梯正在远离或轿厢里有杀人犯则不选。
- 假动作（v3 起）：电梯厅里、附近没有看见杀人犯、距上次假动作超过 `ai.kidBaitCooldown`（40 s）时，按 `ai.kidBait` 概率按一下呼梯就走人。

### 7.2 杀人犯（v6：按序列扫楼，会放弃电梯）

状态机：`搜索 → 追击 → 线索 → 换层`。

- 频道里有情报 → 直奔目标楼层；到层后按情报里的区域搜索。
- 没有情报 → **扫楼（v6 改造）**：沿 `patrolDir` 每次推进 `ai.killerSweepSpan`（3）层，到层后把该层记进 `checked`，`ai.killerCheckedSec`（25 s）内不再重复查；走到端点自动折返。
- 线索（v3）：站在电梯厅读到某部梯停在别的楼层 → 去查那一层（`clueTtl` 15 s，同一层只查一次）。
- **坐错方向就下车（v6）**：在轿厢里发现电梯朝自己目标的反方向走，忍 `ai.killerWrongWaySec`（3 s），到下一个开门站就下车，并且接下来 8 秒优先走楼梯（`forceStairsUntil`），不再干等。
- 追到楼梯口时，如果小孩刚上/下楼梯 → 跟进同一楼梯段。
- 堵门：目标躲进轿厢或在等电梯时，站到门区卡门。

## 10. 技术形态

- 原生 JS 多文件，`<script>` 顺序加载，**双击 index.html 即玩**，无构建、无服务器、无依赖。
- 地图抽成可替换模块：`floorplan-line.js`（1D 走廊，先做）与 `floorplan-grid.js`（2D 俯视，二期）。
- 渲染：Canvas 2D 侧视剖面（楼层横条 + 电梯竖井 + 楼梯竖井 + 墙上呼梯按钮 + 轿厢选层面板）。
- 交互：键盘移动 / 呼梯 / 上下楼 / 进出电梯；鼠标点击呼梯按钮与轿厢楼层按钮（渲染时记录热区，`renderer.hitTest()` 命中）。
- 无头自测：`tools/headless.js`（Node 里用 vm 跑整局，输出统计，便于验证电梯逻辑）。

- **界面重构**：删除左侧常驻参数栏，主界面只保留画布 + 开始/暂停 + 剩余时间（右侧信息栏保留，竖屏隐藏）。
- **暂停菜单**：暂停（P 或按钮）打开菜单，第一页**教程**、第二页**设置**（所有可调数值都搬到这里）。
  - 应用 = 读参数 → 立刻 boot() 重开一局；取消 = 丢弃改动（UI.loadInputs(settings) 回填）→ 回到暂停中的这局；继续 = 关菜单并恢复。
  - 去掉「重开」按钮；「开始」= 新的一局。
- **移动端**：竖屏/窄屏只保留画布、触控栏、剩余时间；UI.readSettings() 强制 mode=escape、view=fog（黑暗视角当小孩）。
- **修长按卡顿**：keydown 的系统重复事件（e.repeat）直接忽略，长按方向键仍然是按住持续走；HUD 的电梯板/分数列表改为内容变化才写 DOM。

### v6.2

- **修「正方向还有任务时为反方向呼梯补开门」**：plan() 里「本层还有反方向呼梯 → 原地补开一次」的判断原先排在「正方向还有任务 → 继续走」**之前**，于是下行经过 16F（有向上呼梯）时会多开一次门，甚至把同层的向下请求一起清掉。现在顺序改为：**先把当前方向的队列跑完**，只有当这个方向真的没有剩余任务时，才在本层为反方向补开一次（serveDir = 0，两个方向一起清）。实测：20F 下行、16F 有↑、轿厢按了 16/1 → 16F 只开一次门后继续下行到 1F；16F 反向呼梯留到下一次上行再服务。

### v6.1

- **修「到站不开门就掉头」**：车正好压在整层线上、同一刻有人按这一层时，move() 先跑了「换向/待机」判断，没先跑「本层要不要开门」，于是门没开就调头走了。现在 move() 第一件事就是：**站着整层且有本层需求 → 立刻开门**（轿厢指令和同向呼梯都算，开门时一并清掉二者的需求）；落地瞬间也补一次确认。40 个「压线按下本层」的组合全部正确开门。

### v6（已部署）

AI 升级（"更像人"，不是超人类）：

- **小孩不再全知**：只记住自己最近 8 秒看见过杀人犯的位置（`ai.kidMemorySec`），形成 ±1 层的危险区；选目标层、同层走动都会避开它（实测危险区被选中的概率 0%）。之前小孩直接读杀人犯真实位置和杀人频道，是作弊。
- **小孩认准目标**：换层后锁定 4 秒不改主意，到站歇 2 秒再决定；实测「10 秒内立刻折返」只占 5%。
- **杀人犯按序列扫楼**：每次推进 3 层，查过的楼层 25 秒内不重复，端点折返。
- **杀人犯坐错方向会下车**：发现电梯朝目标反方向走 3 秒就在下一站下车，并优先改走楼梯 8 秒。
- 参数全部在 `src/config.js` 的 `ai` 段（界面不暴露，避免侧栏过长）。

### v5.4（未提交）

- **开关门键拆成两组**：左侧一组归属 C 梯、右侧一组归属 D 梯（9F–10F 高度），只有身处对应电梯才能按；旁观+上帝视角可以两边都按。
- **左右面板独立算可见性**：小孩在自己乘坐的电梯里看不到另一部梯的按键状态；杀人犯只要有一人待在某部梯里，就能看到那部梯的面板；上帝视角两边都能看到。看得到但没按是暗框，按下是高亮框，看不到则只剩楼层号。
- **事件更细**：进出电梯、在轿厢里按楼层都会记事件；同一层同一方向的呼梯重复按不再重复记录（只体现「等得急」）。
- 修掉开门/关门点击命中的 `carId` 丢失问题（以前会把操作发给错误的电梯）。
- 修掉「空闲电梯里只有轿厢指令时不会动」：plan() 选方向时只查门外呼梯、漏了轿厢里按下的楼层，dir=0 时永远走不到出发分支；现在 
earestCall() 同时看轿厢指令和呼梯。

### v5.1

- **杀人犯视野共享**：玩家当杀人犯时，看到的范围是所有存活杀人犯视野的并集（`Perception.canSeeShared`），电梯读数同理（任一名队友在电梯厅读到就算读到）。频道里的旧情报仍以 `?` 标记。
- **四项速度各自可调**：小孩移动速度、小孩爬楼速度、杀人犯移动速度、杀人犯爬楼速度（`kid.speed / kid.stairSpeed / killer.speed / killer.stairSpeed`），删掉了原来的「楼梯全局速度 × 杀人犯惩罚系数」。
- **视距统一**：小孩与杀人犯共用同一个视距（`kid.vision === killer.vision`，界面只有一个「视距」滑块）。
- **小孩反应时间**：AI 小孩看到杀人犯后要等 `kid.reactionSec`（默认 0.2 s）才开跑。
- **修 config 不生效**：界面滑块现在用 `EK.DEFAULTS` 初始化（`UI.init`），以前滑块写死在 HTML 里、启动时把 config 覆盖掉。
- 默认楼道长改为 1 m；默认成品：小孩 2.2 / 爬楼 0.22、杀人犯 2.6 / 爬楼 0.26、视距 14、反应 0.2。

### v5

### v4

- **键位**：`P` 暂停；`空格` = 按身边按钮 / 进出电梯；`Q`/`E` 在电梯厅 = ▼/▲，在轿厢 = 开门/关门；取消电梯厅的 `W`/`S` 呼梯（`W`/`S` 只管楼梯）。
- 电梯门自动保持时间 1.5 s → **3 s**；轿厢面板新增开门/关门按钮（单独一列）。
- 呼梯按钮位置：C 的两个按钮都在电梯厅左侧、D 的两个都在右侧，按楼层高度对齐（`world.hallButtonSpecs()` 统一给出位置，渲染与点击共用）。
- 「楼道长」下限改为 **0**。
- 停靠只解除**本方向**的呼梯；当一个方向跑完（前方无任务）而本层还有反方向呼梯时，电梯**原地再开一次门**并清掉它（`elevator.reopenForOpposite`）。
- 同一段楼梯是一个空间：**上下两个方向迎面撞上也会被抓**；楼梯上的抓捕判定 1.2 m（`capture.stairRangeM`），楼梯段一层按 4.5 m 折算（`stairMetersPerFloor`）。
- 楼梯口视野：站在楼梯口 1.5 m 内，能看到刚进楼梯间、还没走远（<12%）的人；再进去就看不见了。
- 杀人犯在楼梯上慢 10%（`stairs.killerFactor`），楼梯才是可靠逃生路线。
- 角色拖尾（`trail` 配置，界面不暴露）：淡出渐变；爬楼梯时是一条斜向长拖尾。
